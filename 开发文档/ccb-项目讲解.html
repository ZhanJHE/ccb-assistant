是什么 / 不是什么

一个本地持久化的文献库 + 获取器 + 选题器。核心是一次写清楚的本地优先协议：先查本地库，未命中才走网络；每个渠道的原始响应落盘；字段级 provenance 永不覆盖。

问题机制代码
同一篇论文被反复搜索、下载、抽取本地优先协议 + 内容寻址存储search/acquire.py
无 DOI 的会议论文（OpenReview/PMLR）身份不稳定显式 work_id 键优先级链core/ids.py
多源元数据冲突被静默吞掉字段 → claim 列表，全部保留core/model.py
库损坏不可恢复文本为真相源，索引可删可重建library/index.py
模型凭记忆编文献 / 编等级不产出无锚点论断；未收录 venue 报 unmatchedtopics/

不是什么

  • 不是检索器集合：跨源搜索已是红海，本项目只做组织层，检索走已有渠道。
  • 不是 PDF→Markdown 工具：复用 pdfplumber/pypdf，不重写解析器。
  • 不是生成模型：ask 是检索，topics 只产出证据与骨架。正文由人/agent 写。
  • 不含任何绕过付费墙的路径。见 刻意不做的事。

30 秒上手

# clone 下来即可用，无安装步骤；数据落在 clone 内的 papers/
git clone <repo> && cd ccb-assistant

python ccb.py channels                              # 渠道可用性 + 缺哪个 key
python ccb.py find "diffusion models for molecules" -n 10
python ccb.py get arxiv:1706.03762 --with-pdf       # 幂等：完整则不花钱
python ccb.py open arxiv:1706.03762 --head 20000    # 读本地，零网络
python ccb.py ask "how does scaled dot-product attention work"
python ccb.py cite arxiv:1706.03762                 # 每个字段来自哪个源

# 选题
python ccb.py topics survey "graph neural networks for molecular property prediction"
python ccb.py topics gaps <survey_id>
python ccb.py topics candidates <survey_id>
python ccb.py topics draft <candidate_id>            # 一次只提交一个
python ccb.py topics rate <topic_id> --venue NeurIPS
python ccb.py topics save <topic_id>

全局 flag（--pretty/--library/--offline）写在子命令前后皆可：python ccb.py --pretty doctor 与 python ccb.py doctor --pretty 等价。export 例外：默认输出 JSON，--raw 才输出引用原文（供重定向）。

技术栈与硬约束

语言 / 依赖Python ≥3.10；必需依赖 0 个（只用 urllib/json/sqlite3/hashlib/csv）
可选依赖[pdf] → pdfplumber + pypdf（抽取）；[yaml] → PyYAML（YAML 渠道声明）
stdout 契约永远是 JSON；散文与错误走 stderr（{"error": ...}）
退出码0 ok · 2 用法 · 3 未找到 · 4 部分成功 · 5 失败
Windows 约束控制台默认 GBK，三个入口都强制 UTF-8 stdio；否则含重音/CJK 的标题抛 UnicodeEncodeError
凭据只从环境变量读；写入产物前脱敏；URL 本身可能是 secret，故不落 key
网络--offline 使命令失败而非联网；渠道限速按声明（arXiv 3s/请求）

依赖分层（DAG）

topics   ──→  library, search, core
search   ──→  library, core
library  ──→  core
core     ──→  （不 import 任何自家模块）

规则：模块只能 import 它下面的层。依赖方向自内向外：core ← library ← search ← topics。

这条规则不是注释，是测试：tests/test_modules.py 用 ast 解析真实 import 图（含函数内延迟 import），越界即失败。

重组消除的两个真实环

原状问题归位后
channels/* import evidence.EvidenceStoreL1 反依赖 L2evidence 归 library，成为合法的 search → library
library.py import cite.to_bibtex、passages.chunk_textL2 反依赖 L4cite/passages 归 library，变成模块内引用
extract.py 归谁search（下载后抽取）与 library（重抽取）都要用放 core：放任何一侧都会造出新环

core — 共享底座

文件职责
core/ids.pywork_id 键优先级链、标识符归一化与解析、works 分片路径
core/model.pyWorkRecord/Manifestation/ChannelRecord；claim 追加与源信任序
core/util.py标题/DOI/人名规范化、token 集合、Jaccard、确定性哈希、原子写
core/extract.pyPDF→文本；按页在 pdfplumber / pypdf 间择优；质量分

设计约束：core 不含状态、不碰网络、不碰库文件。它只回答"这一篇论文是谁"和"这段文本怎么规范化"，因此两个业务模块都能安全依赖它。

library — 持久语料

文件职责
library/store.py唯一写路径。upsert/merge/save 同时写记录、索引、账本；记录、claims、manifestations
library/evidence.py原始响应快照（evidence/<ev_id>.json）+ URL 脱敏
library/index.pySQLite 派生索引；self_check 检测漂移并按需重建；永不删除 work 文件
library/passages.py按分页符切段、质量评分、BM25 索引
library/retrieve.pyask()：返回带 work_id + page 的段落，不生成散文

没有网络 I/O——这是被测试强制的不变量（library 不得 import search）。

search — 获取与渠道

文件职责
search/net.pyHTTP：限速、重试、退避、bot 挑战识别、凭据映射与脱敏
search/channels/registry.py注册表：内置渠道 + channels.yaml 声明；可用性汇总
search/channels/base.py渠道契约：caps 能力协商、auth: env:VAR 缺失则降级并报因
search/channels/generic.py声明式渠道：http/cli/mcp 三种 kind，靠 dot-path 字段映射，不写代码
search/acquire.py本地优先协议：find/get/复查；只补齐缺失的部分

渠道声明示例

name: dblp
kind: http
license: CC0                # 数据许可，用于合规审计
auth: none                  # none | env:VAR | keyfile
rate: {rps: 1.0}            # 礼貌限流
caps: [search, lookup, venue]
cs_authority: true          # 是否 CS 身份权威源

凭据透明：渠道声明 auth: env:S2_API_KEY，运行期缺该变量 → 该渠道自动降级为不可用，并在结果的 errors / channels_unavailable 里点名报因。其余渠道照常工作，调用方无需知道谁要 key。

topics — 选题

文件职责
topics/survey.py领域测绘：works/年份/venue（带 CCF 等级）/高频术语；语料不足则自动补齐
topics/gaps.py缺口证据：作者自述句（6 类）+ 稀疏术语对；每条带 work_id + page
topics/operators.py11 个创新算子：创新类型、难度、CCF 上界、消费哪类证据
topics/candidates.py(证据 × 算子) 打分排序；排除已挖过的组合
topics/draft.py章节骨架 + 每条论断的可用锚点；不做正文
topics/rating.py · ccf.pyCCF 评级估计（5 输入可复算）+ 内置目录匹配
topics/store.pytopics/ 产物落盘与去重键退役

核心原则：工具不写散文。模块只产出「结构化证据 + 结构骨架 + 打分与理由」。理由两条：可复现（无模型参与，同输入同输出，可测）与可审计（每条论断能回到某篇论文的某一页）。这条由测试守着：草稿里不可能出现无锚点的论断。

边界如何被测试守住

测试断言
test_no_module_imports_a_lower_layer每个文件的每个 import 目标所属层必须在白名单内
test_core_imports_nothing_from_its_siblingscore 永不 import library/search/topics
test_library_does_not_reach_for_the_network_layerlibrary 不得 import search/topics
test_relative_imports_stay_inside_the_package相对 import 必须解析到 ccb 之下
test_shims_alias_the_canonical_modules旧路径与规范路径是同一个对象（assertIs）

越界即 fail，而不是靠 code review 记得。原因：边界不被测试就会侵蚀。

本地优先协议

整个项目最核心的一段逻辑。它藏在 search/acquire.py，是"不重跑全过程"的具体实现。

get(identifier):
    hit = library.resolve(identifier)          # 本地命中？
    if hit and hit.has_fulltext:  return hit            # 零网络
    if hit and not hit.has_fulltext:  只补全文          # 不重查元数据
    else: 走渠道获取 → 落库 → 返回                     # 首次才走全链路
场景实测耗时网络
首次 get arxiv:1706.03762 --with-pdf（2.2 MB PDF）~5–7 s渠道查询 + 下载 + 抽取
第二次同一命令0.2 s零 —— 直接答"来自本地库"
改用 DOI 查询同一篇0.2 s零，且落到同一个 work_id

检索 → 引用（5 步）

#命令发生什么网络
1ccb find "<topic>" -n 10先查本地；仅未命中部分走渠道，结果顺手落库去重命中则无
2ccb get <id> --with-pdf只补齐缺失的（元数据 / 全文），幂等按需
3ccb open <id> --head N读本地抽取文本无
4ccb ask "<question>"BM25 检索带页码锚点的段落无
5ccb cite / ccb export --format bibtex渲染引用 + 字段 provenance无

幂等性：重复执行第 2 步在已完整的记录上不产生任何网络开销。这是"再问一次不重跑流水线"的落点。

问答（不生成正文）

ask 是检索，不是生成。返回按 BM25 排序的段落，每条带 work_id + page 锚点：

{"grounded": true,
 "hits": [{"work_id": "arxiv:1706.03762", "page": 4, "score": 15.3,
           "citation": "[arxiv:1706.03762 p.4] 2017 Attention Is All You Need",
           "text": "Scaled Dot-Product Attention Multi-Head Attention Figure 2: ..."}]}

若 grounded 为 false，正确回答是"库里没有覆盖这个问题"。工具不会拿它最不差的段落来垫空白；skipped 会列出"有元数据但无存储全文"的作品——因为"没有匹配"和"没有文本可搜"是两件不同的事。

排序是纯标准库 BM25（Okapi，k1=1.5，b=0.75），无模型下载、无 key、无网络，确定性：同一个问题得到同一组引用。

选题（7 步）

#命令返回判断点
1topics survey "<方向>"works/年份/venue（含 CCF 等级）/术语排序/是否够挖sufficient: false（exit 4）→ 说出来并停
2topics gaps <survey_id>作者自述句（6 类）+ 稀疏术语对，均带锚点证据强度
3topics candidates <survey_id>(证据 × 算子) 候选，四部分打分 + 排除已挖排序是阅读顺序，不是预言
4topics draft <candidate_id>章节骨架 + 每节可用锚点 + 数据集/基线（提及次数，非推荐）一次只提交一个，退役去重键
5（人/agent 写正文）—每条论断必须有锚点，无锚点则删掉该论断
6topics rate <topic_id> [--venue X]上界 + 分档 + 置信度 + 逐条依据 + 风险是对估计，不是承诺
7topics save <topic_id>落库 + 导出 Markdown + 退役键—

缺口证据从哪来

① 作者自述句（最强信号）：从全文/摘要抽含标记的句子，带 work_id + page + 原句。中英标记都认（未来工作、未考虑、缺乏…）。按六类打标，因为不同类喂给完全不同的算子：

kind句子在说什么喂给
future_work作者点出下一步transfer, new-setting, revalidate
absence没人研究过fill-absence, transfer, benchmark, integrate
limitation只在某范围成立boundary, paradox
inefficiency规模上太贵scale-up
idealization假设了不现实的东西relax-assumption
breadth太粗、不够具体benchmark, paradox

② 稀疏术语对（可计算的 A+B）：

expected = docs(a) * docs(b) / works     # 若两者独立
deficit  = expected - together
# 仅当 deficit ≥ 1.0 时报告；用文档频次而非出现次数，
# 免得一篇长文把某个词堆成"主题"

11 个创新算子（ccb topics operators 的实测输出）

id动作类型难度CCF 上界消费证据
recombinationA + B → Cfusion3Bsparse_pair
transfer跨学科搬方法application2Cabsence, future_work
new-setting成熟方法，新场景application2Cfuture_work, absence
revalidate新技术重验老问题comparison4Bfuture_work, absence
relax-assumption去掉简化假设modification3Bidealization
scale-up拆掉规模墙modification3Binefficiency
fill-absence做那件"据说没人做"的事modification3Babsence
boundary把局限变成精确条件theory5Alimitation
benchmark多方法放同一协议下比comparison4Babsence, breadth
integrate架起两套理论的桥fusion3Asparse_pair, absence
paradox解释一个被记录下来的矛盾theory5Alimitation, breadth

难度 2–5，沿用领域自己的排序：新问题新方法 > 老问题新方法 > 新问题老方法 > 老问题老方法。算子产出的是问题骨架（含 {a}/{b} 占位），不是句子。

候选打分：四项全摊开

部分权重何时高
directness0.35作者自述缺口（1.0）而非统计推断（0.5）
support0.25该方向多篇工作与这条证据相关
ambition0.20算子难度 2/5 → 0.0 … 5/5 → 1.0
novelty0.20库里共享该候选术语的工作少

四项均以该方向的语料规模归一化（固定分母会让小语料全部饱和成同一列分数，排序失去信息），并逐项写进 score_basis，可手算复核：score = Σ value × weight。同时给出 local_coverage：库里共享该术语的工作清单——先读它们，再说这个组合没人做过。

CCF 评级：五个可复算输入

#输入效果
1算子天花板起点上界
2自述 vs 推断推断扣一档
3语料支撑低于该方向 30% 相关 → 扣一档
4本地覆盖超过 60% 共享术语 → 扣一档
5算子难度≤ 2/5（增量动作）→ 扣一档

--venue X 查表：已知 venue 自身等级封顶，算子天花板低于目标档位时明确警告。未收录的 venue 报 unmatched，绝不从相似名字插值（ai 是 artificial 的子串，错的等级比没有等级更糟）。

增量复查

ccb check --all         # 只重查决定性端点，不重跑全链路
ccb library report      # 变了什么、什么是未知的

"没查到撤稿" 报告为 not found in the sources checked，不报告为 "未撤稿"。缺失信息不等于否定信息。

故障恢复

症状动作保证
索引缺失/损坏/与 work 文件不同步任何命令自检并自动重建，无需手动 reindex索引是缓存，删了可重建
work 文件损坏ccb doctor 报出文件名，ccb repair 重建派生件永不删除/重写 works/*.json
段落索引与全文不一致read_passages 比对 source_sha256，不符则重建派生件不会与源静默不一致
中断的下载先写 .part 再 os.replace内容寻址，同字节永不重复存

为什么纯文本为真相源而不是直接上 SQLite：可 diff、可 grep、可被 agent 直接读、可手工改；派生件删了都能从文本与记录重建——所以不存在"库损坏且无法恢复"，最坏情况只是一次慢重建。

work_id 键链

不用"聪明"的指代消解，而是一条显式优先级链，命中即用，并把"用了哪条"记进账本：

优先级键例
1doidoi:10.1145/3292500.3330701
2openreviewopenreview:abcDEF123
3arxivarxiv:1706.03762
4acl ｜ pmlr:<vol>:<page> ｜ dblp:<key>pmlr:97:1
5t:<规范标题>|<一作姓>|<年>兜底，仅当上面全空

价值：无 DOI 的 CS 会议论文（OpenReview 投稿、PMLR 条目）拿到稳定身份，而不是每次运行都变的标题哈希——标题哈希一变，去重就失效。

两层身份

work_id        概念层：「这篇论文」是谁          稳定、可解释、纯函数
manifestation  载体层：arXiv v1/v2、NeurIPS 正式版、OpenReview 投稿、期刊版

价值：v2 与正式版是同一个 work 的两个 manifestation——PDF 是两份、页码不同、引用应指正式版。现有工具要么当两篇（重复），要么粗暴合并（丢版本信息）。

字段级 provenance

每个字段是一组 claim，而不是一个被反复覆盖的值：

"title": [
  {"src": "dblp",    "val": "Attention is All you Need", "at": "2026-10-11T...", "ev": "ev_8f3a"},
  {"src": "openalex", "val": "Attention Is All You Need", "at": "2026-10-11T...", "ev": "ev_2c19"}
]
  • 显示值按源权威度选一条（publisher of record > dblp > arXiv > aggregators），但所有 claim 都保留。
  • ev 指向 evidence/ 里的原始响应快照 → 任何字段都能追溯到「哪个渠道、什么查询、什么时候」。
  • 多源矛盾（卷号/页码/年份不一致）被看见而不是被吞掉；conflicts 列出分歧字段。
  • 快照先于解析落盘，因此离线可重放、可重建索引、可增量复查。

Git 策略与风险

进 git不进 git
代码、测试、开发文档（docs/、notes/、开发文档/）、Agent Skill、探针脚本整个 papers/——语料、账本、快照、全文、PDF，以及旧的 .ccb/

理由：papers/ 是使用工具产生的数据，不是源码。Git 只跟踪开发产物。

⚠ 高危：git clean -Xdf 会删掉整个语料库

papers/ 被整体 ignore，在该命令眼里全是"可清理的忽略文件"。备份靠整个目录拷贝，不要依赖 Git。

换机 / 备份：拷贝整个 papers/。派生件（passages.json、index.sqlite）可删，works/ 与 files/ 不可丢。
要版本化课题草稿：papers/topics/drafts/*.md 是本地数据；要进仓库请人工导出到 docs/ 或 notes/。这是有意保留的边界。

id规则为什么
single-write-path绝不手工改库文件；一切变更走命令，记录/索引/账本一起写手改会让索引与账本同磁盘真相脱钩
text-is-truthworks/*.json 是真相源，index.sqlite 是派生且可弃删/坏索引永远可恢复，改它不行
self-check-first查询前不要手动 reindex；每条命令自检并重建陈旧索引需要记住的维护步骤一定会被忘记
local-first先查本地库，仅未命中才走渠道这就是全部意义：不再重跑搜索/下载/抽取
no-overwrite字段永不覆盖；新值成为另一条 claim，显示值按源信任序选覆盖会毁掉"发现两个源不一致"的能力

never-answer-from-memory回答只用 ask 返回的段落，并引用 work_id + page无锚点的论文陈述与编造无法区分
