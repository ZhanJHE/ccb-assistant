# 模块设计（维护者参考）

> **定位**：回答"现在代码长什么样、东西在哪、改一个东西要动哪些面"。设计**决策与理由**见
> [设计定稿](设计定稿.md)；按时间的开发记录见[开发工作日志](开发工作日志.md)。
> 行数为 2026-10-13 快照，仅示规模；以代码为准。
>
> **两条总纲**（违反即测试失败，详见 §测试地图）：
> 1. 依赖方向自内向外：`core ← library ← search ← topics`，入口层（cli / mcp_server / ops / contract）调用前三层。
> 2. 所有库变更走 `library/store.py` 的 `save()`——work JSON（真相源）、SQLite 索引（派生）、账本（审计）三者一次写齐。

## 1. 总览

```
入口层   cli/ 包 ── mcp_server.py ── contract.py
              │                │
              └────── ops.py ──┘   ← 三面共用一张表（OPERATIONS / PROMPTS / PAYLOAD_KEYS）
              │
topics/    课题挖掘：survey → gaps → candidates → draft → rate → save
   │
search/    获取编排：Resolver（find / get / check）+ 渠道注册表 + Http 传输
   │
library/   持久语料：store（单写路径）+ index（派生索引）+ evidence + passages + cite
   │
core/      共享地板：model / ids / util / files / extract / paths / sections
```

三面派生：`ops.OPERATIONS` 声明一次（name / group / module / mcp / handler / params /
records_key），CLI 子命令、MCP 工具、契约名单全部派生并互相校验；`ops.PROMPTS`（5 个
MCP prompt 模板）与 `ops.PAYLOAD_KEYS`（36 条命令的输出顶层键）同理。

## 3. library/ ——持久语料

## 5. topics/ ——课题挖掘（六步流水线，每步一个文件）

```
survey(302) → gaps(241) → candidates(417) → draft(486) → rate(254) → save
```

- `survey.py`：测绘语料（按方向聚类、年度分布、top 术语/作者），语料太薄时 `sufficient: false`（exit 4）——**薄是真答案不是失败**。
- `gaps.py`：证据收集——作者自述缺口 + 稀疏词对；`usable: false` 即无证据可用。
- `candidates.py`：（证据 × 新颖算子）打分排序；`operators.py`(278) 定义算子与难度标尺。
- `draft.py`：提交**一个**候选，产出章节骨架 + 锚点引用；`dedup_key` 随即退役（同一组合不再被提出）。
- `rating.py`：CCF 估计 = 上限 + band + 逐条依据 + 风险 + 免责声明——**是估计不是预测**。
- `store.py`(123)：artefacts 落 `papers/topics/`；`commands.py`(182)：CLI/MCP 分发；`ccf.py`(263)：159 场馆目录 + `--verify`。

## 8. 维护手册（常见任务的必动清单）

**加一个 CLI/MCP 命令**
1. `ops.py` OPERATIONS 加一条（name / group / module / mcp / handler / params / **records_key** / **payload_keys**）。
2. 对应 module 写 handler（`ctx.emit(payload)` 的顶层键必须 ⊆ payload_keys 声明）。
3. `tests/test_ops.py` 三面互证自动覆盖；`test_cli.py` 形状锁自动覆盖（补 ARGS 的针对性参数）；contract 自动带出。
4. SKILL.md / references 若涉及新命令，注意 8192 预算配平。

**加一个渠道**
1. `search/channels/` 新文件：`ChannelSpec`（caps / rate_rps / auth / supports）+ `search/lookup/download` + `_parse_*`。
2. `registry.py` 的 `BUILTIN_CHANNELS` 声明（键 → "模块:类"）。
3. `KNOWN_CREDENTIALS`（net.py）登记凭据与缺失后果；渠道表（HTML/README）同步。
4. `test_channels.py` 补解析与短路测试。

**改磁盘格式**
1. 先问：能不能做成**附加可选字段**（dataclass 默认值 + from_dict/as_dict 兼容）？能则零迁移。
2. 不能：`SCHEMA_VERSION`/`LIBRARY_SCHEMA` 升级 + 迁移代码 + 测试（`papers/` 是使用者唯一副本，没有第二份）。
3. 派生件（index / passages）的形状变更：改 `ensure_schema`/`read_passages` 的自愈分支即可，无需迁移。

**加一个索引列**（近期先例：`note`）
1. index.py：works/fts 表定义 + `index_work` 写入 + `ensure_schema` 旧形状检测（缺列/缺 tokenizer → 丢表重建，`_fts_needs_rebuild` 触发一次 `reindex()`）。
2. FTS 的 tokenizer 已是 **trigram**：中文子串可查，但 <3 字 CJK 查询需 `_search_like` 回退（store.search 已内置触发条件）。
3. 测试：往返 + 可检索 + 旧形状升级（test_core.TestExtrasCarryThrough 有完整先例）。
