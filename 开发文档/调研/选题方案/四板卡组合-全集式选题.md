# 四板卡组合选题：RK3588 + VU13P + BlueField + P4 交换机能做什么

> 创建：2026-10-01。前提：手头同时有 **RK3588**（ARM SoC + 6TOPS NPU）、**XCVU13P**（12,288 DSP、≈57MB 片上存储、DDR4 外部带宽弱）、**NVIDIA BlueField DPU**（型号待确认）、**P4 可编程交换机**（型号待确认）。
> 单设备选题已有文档：选题 1（DPU 内联 KV Codec）、选题 2+（VU13P 片上 KV 池）、选题 3/3S（P4 交换机 KV-aware 路由）、选题 4（RK3588 EdgeKV）——见《毕设选题建议.md》《增补-VU13P与纯软件评估路线.md》。**本文只讨论"组合"的增量价值。**

## 1. 核心洞察：四块板 = KV Cache 数据路径的四个阶段

把 PD 分离 LLM serving 里一块 KV 的一生拆开，四块板子恰好各占一段，**没有重叠、没有缺口**：

```
KV 产生（端侧/prefill）          RK3588  ── 边缘 draft/prefill 节点
KV 路由与命中判定（控制面）       P4 交换机 ── 前缀指纹目录、KV-aware 转发、INT 遥测
KV 传输数据面（编解码/搬运）      BlueField ── inline 量化/打包/gather、RDMA
KV 驻留与消费（decode）          VU13P   ── ≈57MB 片上 KV 池 + decode 算子
```

调研已确认的三个空白（见文献索引 NPD/KVT 节）正好被这条链覆盖：
- **在网前缀指纹目录/命中判定**是真空白（NPD 专题，arXiv `"programmable switch" AND "LLM"` 标题级 0 命中）→ P4 交换机段；
- **DPU 内联 KV codec** 无成熟工作（选题 1 论证）→ BlueField 段；
- **片上 KV 池**只有 FlightLLM 思想、无人用大片上存储做"多并发请求的 KV 一等公民"（选题 2+ 论证）→ VU13P 段。

组合起来的故事：**"Re-architecting the KV-cache data path across switch, DPU, and FPGA"** ——把 KV 数据路径的每一段都从 host CPU/GPU 卸到可编程网络与加速器层级。学术圈很少有实验室能同时凑齐这四类硬件，这本身就是护城河。

## 2. 组合选题 A（旗舰）：GPU-free 全卸载 KV 数据路径

**暂定标题**：*OffloadKV: A Fully-Offloaded KV-Cache Data Path for Disaggregated LLM Serving across P4 Switch, DPU, and FPGA*

- **拓扑**：RK3588 当边缘请求源/draft 节点 → P4 交换机（前缀目录 + 路由）→ 主机 A 的 BlueField（inline codec）→ 主机 A/B 的 VU13P（片上 KV 池 + decode）。
- **无 GPU 恰成卖点**：实验室无 GPU 服务器本是劣势，在此架构里变成"整个 serving 数据面不需要 CPU/GPU 参与 KV 搬运"的正面叙事（呼应 Blink 的 CPU-free 定位，但我们连"存储/路由/编解码"三层都卸掉）。
- **拆论文策略（重要）**：整条链工程量 > 1 篇 CCF-B。每个设备段子项目**独立可发**（选题 1/2+/3 各自已有完整论证），组合是集成篇/demo 篇。建议：
  - 第 1 篇：单设备主线（按兴趣选 DPU codec 或 VU13P 片上池）；
  - 第 2 篇：两两组合（如 P4 目录 + DPU codec 闭环）；
  - 第 3 篇（若时间允许）：全链路集成 + 端到端评估。
- **目标场馆**：CoNEXT/ICNP/FPGA/ICCD（会议 B）；TACO/TOS/TCC/COMNET（期刊）。

## 3. 组合选题 B：边缘-云协同推理闭环

**暂定标题**：*EdgeDraft: KV Handoff between Edge SoC and FPGA Decode Pool over a Programmable Switch*

- RK3588 用小模型做 draft 或部分 prefill（SpecEdge, arXiv:2505.17052 的思路），KV/draft token 经 P4 交换机的前缀亲和路由，交给 VU13P 片上 KV 池验证/decode；BlueField 做传输 codec。
- **新颖点**：异构加速器（NPU 边缘 ↔ FPGA 云侧）之间的 KV 交接协议 + 交换机按前缀命中决定"KV 进 FPGA 池还是回 host"——边缘 KV 交接三件套（KVT-28）都没碰"交换机参与交接决策"。
- **测量优势**：RK3588 空载 4-5W/满载 10-12W 的能耗数据 + VU13P 的能效，可以做"每 token 能耗"这条差异化指标，云 GPU 方案给不出。

## 4. 组合选题 C（最快、最低风险）：KV 数据路径逐跳刻画论文

**暂定标题**：*Where Do the Microseconds Go? Characterizing KV-Cache Transfer across Kernel, DPU, Switch, and FPGA Data Paths*

- 逐跳测量同一块 KV 从 prefill 到 decode 的开销分解：内核栈 vs DPDK vs DPU inline vs 交换机辅助 vs FPGA 片上/DDR/PCIe。
- 对标 DBK-46/47/48（SmartNIC 刻画三篇）和 KVT-1（RTT-or-Bandwidth）的方法学——**测量/刻画类论文门槛低、产出快、引用稳定**，且产出的 baseline 数字直接是选题 A/B 的实验地基。
- 适合作为**第一篇**：1-2 个月出活，顺带把四块板子的开发环境全部趟通。

## 5. 动手前必须确认的硬件前提

1. **BlueField 型号**：BF-2 还是 BF-3？BF-3 才有 DPA（DBK-47 的 KV 聚合 4.3× 是 DPA 上的）；BF-2 只有 Arm A72 核，codec 设计要按整型流式算子做。
2. **P4 交换机型号**：若是 Tofino——NPD-17 已记录：Tofino 停产（PCN 827577-00）且 open-p4studio 的 BSP/驱动申请窗口 **2026-01-01 已关闭**。**已有设备可用，但必须立刻确认 SDE/BSP 环境已装好或已有授权**，否则 P4 部分只能退回 bmv2（选题 3S 路线）。
3. **VU13P 板卡形态**：开发板还是 PCIe 卡？DDR4 配置与速率？这决定片上池的"兜底带宽"数字（也是选题 2+ 的核心动机数字）。
4. **不要在 VU13P 上规划有状态 P4**：Vitis Networking P4 截至 WP555(2024-01) 不支持 `register` extern（NPD-16）；FPGA 侧状态用 Verilog/HLS 写，P4 只放交换机上。
5. **RK3588 互连**：只有 ~1G/2.5G 以太网，做组合拓扑时它是"边缘低速端"，别把它放进高带宽 KV 路径的关键链路上。

## 6. 建议推进顺序（对齐 2026-09→2027-05 时间窗）

1. **10-11 月**：确认第 5 节全部硬件前提；跑组合选题 C 的逐跳测量（顺带趟通四个工具链：RKNN、Vivado/Vitis、DOCA、P4 SDE）。
2. **11 月起**：按兴趣与导师意见选单设备主线（选题 1 / 2+ / 3 之一，论证见原文档）。
3. **寒假前后**：两两组合成闭环，攒第 2 篇的实验。
4. **3-4 月**：写作投稿；全链路集成作为毕设 demo，不强求成文。
