## Idea S1：漂移可见的前缀路由（Staleness-Aware Prefix Routing）——⭐ 主线推荐

- **缝法**：A4（Python 模拟器 + Mooncake trace）+ b2（前缀哈希路由）+ b3（漂移建模治理）+ b1（网络打分，可选第三件）
- **一句话**：所有 prefix-aware 路由都假设"KV 驻留索引是新鲜的"；事件驱动的全局索引必然漂移（驱逐/延迟/丢失），漂移导致"指到没有 KV 的节点 → 重算"。**漂移代价没人量化过，漂移感知的路由没人做过**。
- **故事五要素**：背景（prefix routing 成生产标配：llm-d/vLLM/Dynamo）→ 冲突（路由质量依赖索引新鲜度，但索引只能事件驱动、必然陈旧；NetKV 证明"网络遥测陈旧可鲁棒"，**cache 索引陈旧没人管**；HotStorage'26 只给一致性抽象没给系统数字）→ 主角（漂移感知路由器：staleness 打分项 + 轻量确认/回退 + epoch 失效）→ 情节（模拟器 × 生产 trace × 漂移注入实验）→ 主题（**索引新鲜度是路由质量的第一类变量**，与命中率、负载并列）。
- **三实验**：① 对比：llm-d 近似/精确两版、NetKV 式、RR、理想全知（oracle）② 消融：A → +漂移模型 → +staleness 打分 → +治理（每步报告，含负步）③ 实例：漂移率-重算量曲线、确认开销分解。
- **诚实设计**：≥10 seed 全报告（mean±std）；trivial baseline = 周期性全量同步；**Go/No-Go G1**：漂移注入下 baseline 退化不显著（<5%）→ 前提不成立 → 转 S4 测量线。
- **撞车**：NetKV（相邻不重叠：管网络陈旧不管索引陈旧）；HotStorage'26（理论侧）；llm-d（baseline）。
- **可跑性**：✅ Windows 原生（Python 模拟器）。目标场馆：Computer Networks / CoNEXT / ICNP（CCF-B）。

## Idea S2：检索层 × 网络的联合路由（Retrieval-Network Joint Routing）——备选（撞车风险高）

- **缝法**：A2（SGLang）或 A4 + b5（retrieval-as-control-plane）+ b1（network oracle）
- **一句话**：Tessera 用检索需求做路由/保留但不看网络状态；NetKV 看网络但不懂 KV 内容需求 → "需求 × 驻留 × 网络"三元联合路由。
- **故事**：RAG/agent 记忆场景 73.9–76.3% 复用在非前缀位置（Tessera 数字）→ 需求可知但路由短视 → 三元打分 → TTFT 与均衡双优。
- **撞车**：⚠️ Tessera 太近（2026-09 新稿），差异化窗口小；除非 S1 的漂移维度缝进来（b5+b1+b3 三件），否则暂缓。

## Idea S3：DPU 前缀目录代理（判定下沉网卡）——硬件线（待环境确认）

- **缝法**：A1（vLLM+LMCache）+ b8（ShadowServe 分控形态）+ b2（前缀指纹目录下沉 DPU）
- **一句话**：ShadowServe 把**取回/解压**下沉网卡但**命中判定留在 host CPU**；把判定也下沉（目录在 DPU），消灭 host 控制面一跳，判定延迟 µs 级。
- **故事**：全局 KV 池时代每次复用都要问控制面 → 判定本身成延迟/CPU 税 → 网卡目录（热集）+ host 索引（长尾）分层 → 主题=控制面/数据面边界重划（与 NVIDIA CMX 工业路线正面切分：它做路由/复用/放置，**未做命中判定下沉**）。
- **撞车**：ShadowServe（切分点明确：判定 vs 取回）；CMX/DOCA Memos（工业，需每 2 周盯）。
- **可跑性**：需 BF-2/3 + GPU 服务器（**待确认**）；无硬件时用 A4 模拟器降级验证策略。

## Idea S4：跨请求 KV 内容级重复率 + 索引漂移代价（测量论文）——⭐ 最稳，先行

- **缝法**：A5（公开 trace 分析）+ ATC'25 KV$-wild 方法 + b10（replay 方法学）
- **一句话**：社区都在建全局 KV 索引/目录（llm-d、CMX、Tessera、我们 S1–S3），但两个基础数字没人公开：**① 跨请求内容级重复率上限（非前缀 vs 前缀）；② 索引漂移的重算代价**。我们测出来——数字高 = S1–S3 的动机弹药；数字低 = 泼冷水论文（ElasticKV 已证明该形态能发）。
- **故事**：背景（全局 KV 索引建设热）→ 冲突（两个基础数字缺失，大家在沙滩上盖楼）→ 主角（测量框架 + 公开 trace 复现）→ 情节（三条 trace × 多模型 × 重复率/漂移矩阵）→ 主题（给社区一个可复用的 trace 分析 + 边界结论）。
- **可跑性**：✅ Windows 原生纯分析，2–3 周可出初稿。**同时是旧待办（NPD 调研 §10 最后一项）销项**。

## Idea S5：跨模型 KV 目录（Cross-Model KV Directory）——趋势线，高风险高回报

- **缝法**：A1 + b12（跨模型映射）+ b6（选择性重算）+ 跨模型前缀目录（哪台机的哪个模型持有哪段可映射 KV）
- **一句话**：Gateway 时代同一会话跨模型切换（RaReCache 解决精度、DroidSpeak 解决同族），但"**谁的 KV 能映射给谁、代价多少**"这个目录与路由问题没人管。
- **撞车**：RaReCache/DroidSpeak 在精度侧；目录/路由侧暂空白，但跨模型 KV 线正在快速增密（KV-Lingo、Cross-Model Transfer、UAG），窗口期可能只有 2–3 个季度。
- **建议**：挂哨兵观察，S1/S4 出成果后再决定是否切入。

## Idea S6：诚实负面结果预案（防御性，内嵌于所有 idea）

- 学 ElasticKV 范式：每个 idea 的实验计划里**预写**"若效果不显著 → 转诚实负面结果 + 边界条件"的退路（ElasticKV 证明"机制 + 诚实负结果 + 边界陈述"可以成文）。**坏结果不是"没做过"，是论文的分析章节。**
