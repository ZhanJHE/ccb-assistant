## J1 — ETC 的"跨协议漂移"鲁棒增强（首选）
- **一句话命题（可证伪）**：把 ETC 从"同分布刷分"改成"**跨协议域**"评测后，加一个**域泛化模块（对比/对抗/域适应）**能让跨域 F1 相对 baseline 提升 **≥ Δ**（Δ 事前冻结）；否则该模块无价值。
- **🔧 缝料**：骨架 = **NetGPT**（arXiv:2304.09513，有代码）/ **ET-BERT**；模块 = 对比预训练、域适应（DB `module domain adapt`）、跨域分词（PeerJ'25）；数据 = USTC-TFC / UNSW / CIC。
- **🔪 审稿人**：新颖性 = "**跨协议域**"这一设定（现有 ETC 多在同一数据集内拆 train/test）。最危险邻居：AIN-10（PQC 跨域）、PeerJ'25（跨域分词）。
- **🔧 工程师**：baseline 有代码；单机 CPU/单卡可跑；三实验 = 对比(ET-BERT/NetGPT) / 消融(去域泛化模块) / 跨域(协议参数化漂移)。
- **🧊 泼冷水**：**命门**——若加模块后跨域 F1 提升 **< Δ**，或同分布代价 > δ → 不成立。最小证伪实验：在一个协议迁移方向上跑 baseline vs +模块。
- **成本**：低-中 ｜ **可宣称**："首个跨协议域的 ETC 鲁棒增强" ｜ **不可宣称**：新预训练范式。

## J2 — NIDS 的"基准漂移感知"评测（最危险邻居已占位，须差异化）
- **一句话命题**：公开 NIDS 基准（UNSW/CIC）**自身的版本/采样漂移**会改变模型排名；把"基准版本"当成一个**评测轴**后，排名会再次翻转。
- **🔧 缝料**：骨架 = **AIN-18 harness**（已 clone）；模块 = 特征选择（SHAP-Guided FS, Access'26）、时间/版本切分；数据 = UNSW/CIC NetFlow v2。
- **🔪 审稿人**：**最危险邻居 = Benchmark-Shift-Aware IDS（Electronics'26）**——它已经叫"benchmark-shift-aware"，**我们必须正面切分**（我们的差异 = 把它做成"轴"并与其他三轴联合量化，而非又一个检测器）。
- **🧊 泼冷水**：**命门**——若基准版本变化引起的排名变化不显著 → 该轴无独立价值。
- **成本**：低 ｜ **撞车**：高（**先做 G0 复核再投入**）｜ 备注：可作为 **NIDS 多轴项目（M3）的一个子实验**，不必单独立项。

## J3 — 加密流量的 MoE 分类
- **一句话命题**：加密流量呈**异构多模态**（包序/时序/字节），用 **MoE（专家路由）**替换单塔模型能在**异构子集**上取得可测增益，且总参数量不增太多。
- **🔧 缝料**：骨架 = ET-BERT；模块 = **MoE**（DB: DAIR-FedMoE, TDSC'26）、LoRA；数据 = USTC-TFC/CIC。
- **🧊 泼冷水**：**命门**——若 MoE 相对同参数单塔无显著增益 → 不成立（MoE 常是"看起来新"的灌水重灾区，必须给**参数对齐**的对照）。
- **成本**：中（训练 MoE 更贵）｜ 最适合作为 J1 的"模块变体"打包。

## J4 — 联邦 + 持续学习抗 ETC 漂移
- **一句话命题**：把 ETC 训练改成"**联邦 + 持续学习**"后，能在不共享原始流量的前提下，把跨域/漂移下的退化降低 ≥ Δ。
- **🔧 缝料**：骨架 = ET-BERT；模块 = **Federated Continual Learning for ETC**（Electronics'26，现成思路）、域适应；可单机用多进程模拟 client。
- **🧊 泼冷水**：**命门**——若持续学习引入灾难性遗忘、Net 增益为负 → 不成立。
- **成本**：中（可单机模拟，但要写 federated 循环）。

## J5 — LLM 流量预测的"捷径审计"（= v1 I5，缝料已齐）
- **一句话命题**：LLM 流量预测（ST-LLM / CoT-ICL）的高分部分来自**捷径/泄漏**；用 AIN-18 的免训练审计法（solo-F1 stump + 分阶段消融 + 跨域转移）能给出其**真实泛化上限**，且显著低于报告值。
- **🔧 缝料**：骨架 = AIN-18 审计法（`ablation_experiment`）；模块 = 特征消融、跨城/跨时转移；数据 = 公开蜂窝/骨干流量。
- **🧊 泼冷水**：**命门**——若消融后性能不显著下降 → 证伪。
- **成本**：低 ｜ 撞车：低-中。

## J6 — 在网概念漂移检测（软件仿真评测）｜**需硬件**
- **一句话命题**：数据面内 IDS（iGuard/FSNIC）冻结部署后在漂移下退化更严重，且**缺少数据面可算的漂移检测**；用"轻量漂移检测 + 控制面重训/热替换"闭环可恢复 ≥ Δ。
- **🔧 缝料**：骨架 = **iGuard**（可编程交换机内 Isolation Forest）/ **FSNIC**（FPGA LogicNets 流级 IDS）；模块 = **Adapting at Line-Speed**（SIGCOMM'25 demo）的漂移检测；平台 = bmv2（软件）→ 升级 VU13P。
- **🧊 泼冷水**：**命门**——若漂移退化 < A%，或其脆弱性不显著高于软件 IDS → 不成立。
- **成本**：中 ｜ **本机**：△（先 bmv2 软件仿真；**不碰 WSL**，Linux 部分待用户/云端）。**这是 v1 的 I3，最贴"在网"主线。**

## 与 NIDS 多轴项目（已立项）的关系

- **J2 / J5 / J6** 都可作为 **NIDS 多轴项目** 的子实验或后续论文（同一套 harness/数据，边际成本极低）。
- **J1 / J3 / J4** 是 **ETC 线**（独立方向，共享"跨域鲁棒"母题）。
- 建议路线：**先把 NIDS 多轴跑出结果（M1）→ 用同 harness 顺产 J2/J5 → 再决定是否开 ETC 线（J1）**。
