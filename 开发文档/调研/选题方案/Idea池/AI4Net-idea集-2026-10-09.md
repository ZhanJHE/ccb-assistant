## I1 学习型拥塞控制"鲁棒性矛盾"的评测学归因（首选）
- **可证伪命题**：AIN-26（学习型 CC 在动态条件下**劣于** Cubic/BBR）与 AIN-27（学习型 CC 在对抗下**优于**传统 CC）的**相反结论**，可由**评测轴 + 对抗强度/约束 + 指标选择**的差异**单变量**解释；在统一 Mininet+Mahimahi harness 下固定变量即可复现两端并给出"学习型何时占优"的**边界曲面**。
- **🔪审稿人**：新颖性来自"**解释域内矛盾**"而非再测一遍；需保证不是"综述式复读"——必须给出**可预测的边界条件**与可复用的"CC 鲁棒性报告卡"。
- **🔧工程师**：两篇**代码均开源**（AIN-26 的 figshare、AIN-27 的 Mahimahi 实现）；单机 Mininet + 网络 namespace 即可；3 个 CC（Orca/Astraea/Cubic）+ 1 个对抗 agent。
- **🧊泼冷水**：**命门实验**——若在统一 harness 下把"对抗强度"从 0 扫到最大，"学习型 vs 传统"的相对优势**不随强度单调反转**（即两篇结论无法用强度解释），则命题不成立 → 止损。
- **最危险邻居**：AIN-26、AIN-27 本身（占位了各自的 harness）；Mazilu/Giacomoni 组。
- **最小闭环**：复现 AIN-26 的 dumbbell 公平性实验 + AIN-27 的特征级/环境级对抗 → 叠一张"优势 vs 强度/动态性"的相图。成本：**低**（1 台多核 PC，CPU bound）。
- **可宣称 / 不可宣称**：可宣称"给出矛盾的可解释边界 + 报告卡"；**不可**宣称"新的学习型 CC 算法"。

## I3 在网/近线 IDS 的"漂移下在线维护"（主线首选）
- **可证伪命题**：数据面内 IDS（iGuard 可编程交换机内 Isolation Forest；FSNIC FPGA SmartNIC 内 LogicNets）**一旦部署即冻结**，在**流量/协议漂移**下退化显著，而现有工作**无一测漂移、无在线维护机制**；提出"轻量漂移检测（数据面可算）+ 数据面外重训/热替换"的闭环，可把漂移后精度恢复到接近部署初值，且维护开销可量化。
- **🔪审稿人**：把 AI4Net 推到"在网/线速"，且**正面回答 `#空白5`**；差异化 = "**部署后维护**"这一被忽略的一维，而非再造 IDS 模型。
- **🔧工程师**：用 **bmv2/P4**（本组有 P4 环境）+ 公开 trace（UNSW/CIC 已用于 iGuard/FSNIC）+ 复现 iGuard 的 IF / LogicNets 编码；漂移可用 AIN-10 的协议漂移范式或时间切分制造。
- **🧊泼冷水**：**命门实验**——若数据面 IDS 在漂移下退化 **<A%（且不比同类软件 IDS 更脆）**，则"漂移脆弱"前提不成立 → 止损重选（A、阈值需在开题时事前冻结）。
- **最危险邻居**：iGuard（AIN-16，在网 IF 但不测漂移）、FSNIC（AIN-19，流级但不测漂移）、AIN-6（漂移实证，但纯软件离线）。
- **最小闭环**：bmv2 上跑"冻结的"数据面 IDS → 时间切分制造漂移 → 量化退化 → 加一层漂移检测+重训闭环。成本：**中**（需 bmv2;若 VU13P 网口可行则升级为硬件兑现）。
- **可宣称 / 不可宣称**：可宣称"首个在网 IDS 漂移鲁棒性测量 + 轻量维护闭环"；**不可**宣称新检测算法。

## I4 网络 Agent 的执行期护栏（意图 → 可验证断言）
- **可证伪命题**：现有 LLM Agent 网络基准（NetConfArena）只做**事后**结果验证；把 operator intent 编译为**运行时可检查的不变式断言**（配置→行为），可在 Agent **执行前/中**拦截偏离意图或危险动作，**不牺牲（甚至提升）任务成功率**。
- **🔪审稿人**：从"评测"升级为"**runtime guardrail**"是新维度；但 NetConfArena 刚开源自带可执行测试用例 → 必须证明"**在线拦截**"比其"离线测试"多出可量化的安全收益。
- **🔧工程师**：复用 NetConfArena（开源）+ Mininet/容器沙箱 + LLM API；把隐藏测试用例改造成"逐动作断言"。
- **🧊泼冷水**：**命门**——若护栏**拦不住（误报/漏报高）**或**显著降低任务成功率**（>5%），则不成立。
- **最危险邻居**：**NetConfArena（AIN-40）**、Network Arena（AIN-41）、NDT Factory（AIN-43，语义模型→可验证）。
- **最小闭环**：在 NetConfArena 的 96 模板里挑协议类任务 → 加断言层 → 对比护栏前后成功率与危险动作拦截率。成本：**中**（LLM API 花费 + 沙箱工程）。
- **备注**：撞车风险**最高**（2026 该方向论文密集），需非常明确的差异化。

## I5 LLM 流量预测的"捷径/泄漏"审计
- **可证伪命题**：LLM 做流量预测（AIN-28 ST-LLM、AIN-38 CoT-ICL）报告的高分有相当部分来自**捷径/泄漏**（时间戳、站点身份、序列位置、跨集重复）；用 AIN-9/18 的免训练审计法（solo-F1 stump 标记 + 分阶段消融 + 跨城/跨时转移）可给出其**真实泛化上限**，且上限显著低于报告值。
- **🔪审稿人**：审计型贡献在 2026 被顶会接受（AIN-9/17/18 已证）；需保证不是"小型复现"。
- **🔧工程师**：公开蜂窝/骨干流量数据集 + 开源时序 LLM；CPU/单 GPU 可跑。
- **🧊泼冷水**：**命门**——若消融泄漏特征后性能**不显著下降**，则"捷径"命题证伪。
- **最危险邻居**：AIN-18（审计法已给出，需说明迁移到"预测"而非"检测"的新意）、AIN-28。
- **最小闭环**：选 2 个公开数据集 + 2 个 LLM 预测器 → 审计 → 报"消融前后"差距。成本：**低**。

## I2 加密流量的"协议漂移合成器"
- **可证伪命题**：无需等真实 PQC 部署，可用**协议参数化合成**（TLS 扩展/密钥长度/分片/记录层切分）生成"未来域"trace；且合成域上暴露的 ETC 跨域退化**排序**与 AIN-10 的**真实 PQC 域**排序一致（Kendall τ ≥ 阈值）。
- **🔪审稿人**：把 AIN-10 的"被动观测漂移"升级为"**主动合成漂移**"，是方法学推进；风险是"合成不真实"。
- **🔧工程师**：用 openssl/BoringSSL 改参数采集 trace；拿公开 ETC 模型（YaTC/ET-BERT，AIN-10 已给代码）。
- **🧊泼冷水**：**命门**——若合成域与真实域的退化**排序不一致**，则合成器无预测价值。
- **最危险邻居**：AIN-10（真实 PQC 基准）、AIN-8（生成式 ETC 合成数据，但目标是造训练数据不是造评测域）。
- **最小闭环**：合成 ≥3 个"未来域" + 复现 AIN-10 泛化实验 + 算排序一致性。成本：**低-中**。

## I7 学习型 NIDS 的"第四轴"：时序/概念漂移
- **可证伪命题**：AIN-18 的三轴（同分布/跨域/对抗）漏掉**时序漂移**；加入第四轴后模型排序会反转（如同跨域 vs 对抗那样），说明"多轴评测"必须再加一维。
- **🔪审稿人**：直接扩展一篇 2026 新作，新颖性有限但**门槛低**；适合作为 I5/I1 的副产物或备选。
- **🔧工程师**：复用 AIN-18 的开源 harness（github.com/ebadatif/IDS-three-axis-evaluation）。
- **🧊泼冷水**：**命门**——若加时序轴后排序不变，则"第四轴"无独立价值。
- **最危险邻居**：AIN-18（三轴）本身。
- **最小闭环**：在其 harness 上加时间切分轴 → 报排序变化。成本：**低**。

## I6 数字孪生"保真度—可验证性"统一基准
- **可证伪命题**：NDT 号称保真但缺可复现度量；定义"**孪生—真网一致性**"指标（配置→行为预测误差）并在 ≥2 开源孪生上测，可量化"合成型（NDT Factory）vs 手工型"孪生的一致性差距。
- **🔪审稿人**：与 AIN-37 综述、AIN-43 NDT Factory 相邻；需避免"只是又测了一遍"。
- **🔧工程师**：Mininet/容器 + 开源孪生 + 离散事件仿真。
- **🧊泼冷水**：**命门**——若两类孪生一致性无显著差异，则该基准无区分度。
- **最危险邻居**：AIN-43、WTP-111（WiFi 数字孪生综述）。
- **最小闭环**：≥2 孪生 × ≥3 拓扑 × 一致性指标。成本：**中**。
