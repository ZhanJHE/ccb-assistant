## I1 · 在网 ML 的漂移解剖与热更新机制（Drift Anatomy + Hot Update）⭐推荐主线

**一句话**：首次定量刻画"在网 ML 上线即静态"的漂移衰减曲线，并给出数据面漂移检测 + 控制面热更新的完整闭环与"何时更新"的成本模型。

**现象与证据（非平凡现象候选 #1）**：
- 所有在网模型是静态的；而**全部 SOTA 都把"更新"自陈为未来工作**——Synecdoche future work ①②（波动影响+规则更新）、LOBIN 阈值手动调、ACORN §9、SpliDT 自适应窗口（精读 §1–§5）。
- 主机侧已有漂移退化证据：AIN-6（漂移下 ETC 显著退化）；在网侧唯一碰漂移的是 Chimera two-timescale，但只做 map 自适应、不做模型更新（精读 §6）。
- 在网更新的特殊性（没人量化过）：**更新 = 刷表项 = churn 代价 + 瞬时不一致**（P4runpro 只给机制不给策略）。

**做法**：
- Baseline（全开源）：Synecdoche（GitHub）+ BoS（GitHub）+ 树模型 baseline（NetBeacon 式 top-k，可复用 SpliDT 的 Range Marking）。
- 三实验：① **漂移衰减测量**（3 数据集 ISCXVPN2016/CICIOT2022/ToN-IoT × 3 模型 × 时间外样本切分，画出"部署后精度-时间"曲线——这张图本身就是核心贡献）；② **机制**：数据面轻量漂移检测（PSI/KS on 特征分布 sketch）+ epoch 表项热切换 + 更新成本模型（churn vs 精度损失的平衡点）；③ **端到端**：热更新闭环 vs 静态模型 vs 每日重训 oracle 的精度-成本 Pareto。
- 故事：背景（在网 ML 五年积累都在解决"部署"）→ 冲突（部署后模型 silently 过期，且更新有独特代价）→ 主角（漂移解剖 + 热更新闭环）→ 情节（衰减曲线 + 闭环机制 + 成本模型）→ 主题（**在网 ML 需要生命周期管理，不只是部署**）。

**三视角**：
- 新颖性：高——"在网 ML 更新"无人做（最接近：Chimera map 自适应、P4runpro 机制层、ACORN 刷表工程基础）；测量部分独立成立。
- 可行性：bmv2 可起步、Tofino 存量可加强；数据集公开；baseline 开源；周期 6–8 个月可控。
- 撞车：Chimera（已切分：它做特征 map 自适应，我们做模型生命周期）；主机侧概念漂移文献海量但都不涉及数据平面约束（churn/表项/线速检测）——切分点清晰。
**目标场馆**：Computer Networks / ToN / CoNEXT / ICNP。
**止损线**：若 3 个数据集上漂移衰减都不显著（某些 IDS 数据集时间结构弱）→ 退化为"在网 ML 生命周期测量文"（与 I2 合并）。

## I2 · Revisiting In-Network ML：统一评测与收益边界（SoK/测量文）

**一句话**：用统一 harness（同数据集划分、同硬件、同特征预算）重测 5–6 个代表性在网 ML 系统，给出"何时哪条路线真的赢"的决策图与资源-精度 Pareto 谱系。

**现象与证据（非平凡现象候选 #2）**：
- 谱系内互批全部基于"作者自己重实现别人的 baseline"：BoS vs N3IC/NetBeacon、SpliDT vs NetBeacon/Leo、Synecdoche vs BoS/NetBeacon（精读 §1/§4/§7/§9）——**没有一次对比是在相同数据划分+相同硬件上做的**。
- 先例：NCB-2《Revisiting INA》（ToN'25，聚合侧收益重估）——在网推理侧 equivalents 空白（卷宗 §7 空白 6）。
- 现象池 #3/#4 可作核心发现候选：量化-精度悬崖形状各异；recirculation 的带宽代价被报、延迟代价被藏（Quark 102 recirc→42.66µs vs Synecdoche 416ns）。

**做法**：
- 复现集：树系（IIsy/Planter 或 NetBeacon 式 top-k）+ SpliDT 式 + NN 系（BoS、Quark-本组）+ 匹配系（Synecdoche）+ 混合系（LOBIN 式 escalation）。
- 三实验：① 统一基准（2–3 个共同数据集：ISCXVPN2016/CICIOT2022/Bot-IoT，同 80/10/10 划分）；② 资源-精度 Pareto（SRAM/stage/流数/位宽扫描）；③ **压力测试**：多类扩展（5→42 类）+ recirc 延迟解剖 + 漂移敏感性（与 I1 共用测量设施）。
- 故事：背景（五年 20+ 系统，各自报喜）→ 冲突（数字互不可比，后来者不知道该抄谁）→ 主角（首个统一评测）→ 情节（决策图：任务类型×资源预算→最优路线）→ 主题（**在网 ML 的"赢"是有条件的，我们给出条件**）。

**三视角**：
- 新颖性：中——SoK 型本身不新，但"在网 ML 统一评测"无人做；核心发现决定上限。
- 可行性：全部开源/本组代码；工程量是最大风险（5 系统复现）→ 砍到 4 个。
- 撞车：Zheng & Zilberman COMST'23 / Parizotto CSUR'23 是定性综述，无定量复现；AIN 侧"评测可信度危机"系列（AIN-9/10/17/18）证明这类工作当下被接受。
**目标场馆**：Computer Networks / ToN / IMC（测量会）/ CoNEXT。
**止损线**：若统一后结论只是"各有所长"（无锋利现象）→ 降级 workshop/short paper，或把测量设施并入 I1。

## I3 · 推理→动作闭环：在网分类驱动的线速流量工程（Actuation Loop）⭐本组衔接最好

**一句话**：让在网分类器的输出**直接在数据平面**驱动转发/限速/遥测动作（无控制面往返），给出"检测-动作"闭环的延迟-精度-误伤代价模型。

**现象与证据（非平凡现象候选 #5）**：
- 几乎全部在网 ML 止步于"看见"（检测/分类），例外只有 LOBIN（金融动作）与 Chimera 一句带过（精读 §跨论文观察 B5）。
- 本组资产直接衔接：SPRINT（INT 遥测线速恢复）提供"观测-反馈"通道、Carlo 提供跨平面协同部署——闭环的另一半现成。
- 动机数字现成：BoS/Synecdoche 的早判位置（第 6–12 包）意味着动作可以在流的前 1% 生命周期内生效——**"早判早动作"的定量收益没人算过**。

**做法**：
- 系统：Synecdoche 式匹配（或 Quark CNN）+ 数据面动作原语（限速 meter/reroute/mirror-drop）+ SPRINT INT 回传效果确认；场景二选一：DDoS 缓解（检测→限速）或大象流负载均衡（检测→reroute）。
- 三实验：① 闭环延迟（检测位置→动作生效的包序号/时间）vs 控制面方案（两个数量级差异预期）；② **误动作代价模型**（误分类→错误限速的良流损失，给出精度-阈值的误伤曲线——这是审稿人必问的）；③ 与 SPRINT 联动的端到端 demo。
- 故事：背景（在网 ML 五年=看见）→ 冲突（看见不动作，价值打折；控制面闭环 ms 级，错过窗口期）→ 主角（数据面推理-动作闭环）→ 情节（两场景+代价模型）→ 主题（**in-network intelligence 的下一步是 in-network actuation**）。

**三视角**：
- 新颖性：中高——"检测→线速动作闭环+误伤模型"未见占位（需复核 iGuard/QCNN 的缓解侧）；但"检测+动作"工程组合的嫌疑要靠代价模型洗掉。
- 可行性：Tofino 存量 + 本组 SPRINT；baseline 开源；场景数据集公开（Bot-IoT/CIC-DDoS）。
- 撞车：iGuard（CoNEXT'24，交换机内 Isolation Forest 检测——缓解动作未做）；QCNN（JNSM'26，检测+缓解？**待核实**）；NetChain 式数据面状态机无 ML——切分点=ML 驱动的闭环+误伤模型。
**目标场馆**：CoNEXT / ICNP / IWQoS / Computer Networks。
**止损线**：若"动作"只能做成工程组合、代价模型无非平凡发现 → 与 I1 合并（漂移检测→限速动作作为 I1 的应用场景）。

## I4 · 发现-匹配范式移植：在网 KV 前缀命中判定（交叉子方向 II，上限最高）

**一句话**：把 Synecdoche 的"离线发现判别片段→range 表项在线匹配"移植到 LLM KV 前缀命中判定，实现子方向 II 已验证空白（在网前缀指纹目录）的线速数据平面判定。

**现象与证据**：
- 子方向 II 空白 2 经两轮独立验证仍零占位（[在网KV前缀去重调研](../../调研卷宗/在网计算-LLM/在网KV前缀去重调研.md)：arXiv 双查询 0 命中 + 两路撒网 0 命中；2026-10-10 增量复查仍成立）；需求侧 ATC'25 生产 trace 理想命中率 62%/54%。
- 机制移植的接口：KV 前缀命中 = "最长连续命中链式哈希序列" 与 Synecdoche 的"滑窗寄存器+range 表项匹配"同构（逐块匹配、命中即返回）；机制移植是子方向 I 分叉认证的"缝的主要形态"。

**做法**：
- 数据面：prompt 的链式 block 哈希序列进滑窗寄存器 → range/exact 表项匹配前缀指纹目录（热集）→ 命中位图返回；控制面：vLLM KVEvents 驱动表项 epoch 更新（复用 I1 的热更新机制！）。
- 三实验：① 判定延迟/线速 vs llm-d（软件索引 baseline）；② 索引漂移的重算代价（与子方向 II 空白 3 联动）；③ 热集容量-命中率曲线（NetCache 式小缓存效应）。
- 故事：背景（KV 前缀复用是 LLM serving 最大单项优化）→ 冲突（命中判定全在主机软件，不线速、有漂移）→ 主角（发现-匹配范式的在网前缀目录）→ 情节（三实验）→ 主题（**把"判定向"下沉到数据平面，索引上交换机**）。

**三视角**：
- 新颖性：最高——空白经两轮验证；且 I1 的热更新机制可直接复用为"目录 epoch 失效"（两篇可互相引用支撑）。
- 可行性：需要 vLLM/llm-d 环境 + Tofino/bmv2；跨两个子方向背景，复杂度高；8 个月偏紧。
- 撞车：llm-d KV-Cache Indexer（软件 baseline）、CableCache（请求级去重）、ShadowServe（命中在 host）——切分已在子方向 II 卷宗写好。
**目标场馆**：CoNEXT / ICDCS / Computer Networks；若做成可冲 NSDI。
**止损线**：若语义改造成"链式哈希+位图"在 stage 预算内不可行 → 退回纯软件仿真版投 B 类期刊。

## I5 · 在网自适应早退推理：Quark 的 recirculation 削减（本组最近起点）

**一句话**：给 Quark 的 CAP-Unit 加"按流早退"能力——简单流在少数 recirculation 内提前出结果，把在网 CNN 的推理延迟从常数 42.66µs 变成按难度分布。

**现象与证据（非平凡现象候选 #4 的正面版）**：
- Quark 102 次 recirc→恒定 42.66µs（精读 §2）；BoS/Synecdoche 证明**判别信息在流上分布极不均**（Synecdoche 95% 样本第 10 包前可判；BoS escalation 只需 2.77–5.22% 流升级）——"早退"有坚实的经验基础。
- 早退（early-exit）在主机 ML 是成熟概念，**在网侧未检索到**（待子代理核查）。

**做法**：
- Baseline：Quark（本组开源）；机制：每个 CAP-Unit 出口加置信度估计（BoS 式累计概率/focal 训练）+ 早退阈值表项；对照实验：精度-延迟联合分布（不是单点延迟！）。
- 三实验：① 精度损失 vs 平均 recirc 次数曲线；② 尾延迟/抖动改善（呼应现象池 #4"recirc 延迟代价被藏"）；③ 与 Synecdoche/纯 Quark 的三方对照。
- 故事：背景（在网 CNN 已证明可行-Quark）→ 冲突（恒定全模型推理=简单流也付全价）→ 主角（按难度自适应的早退推理）→ 情节（三实验）→ 主题（**在网推理从"能跑"到"会省"**）。

**三视角**：
- 新颖性：中——early-exit 概念成熟，但"在网+按流+recirc 预算"组合未见；**最大风险是与本组 Monic（MoE 专家选择=另一种自适应）边界**——必须等 Monic 公开稿核对后立项。
- 可行性：本组代码+Tofino；周期最短（3–5 个月可出原型）。
- 撞车：主机 early-exit 文献（BranchyNet 等）不构成撞车（场景约束完全不同）；Monic 是内部撞车风险。
**目标场馆**：INFOCOM / ICNP / CoNEXT；或并入 Quark 期刊扩展版（IEEE TC/ToN）。
**止损线**：若 Monic 已覆盖自适应推理 → 放弃独立成文，转为 Quark 期刊扩展的一节。
