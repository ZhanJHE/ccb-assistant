## 一、B 档主攻候选（重排后）

### A 线 · 交换机侧信号驱动分离式 LLM serving 调度（天花板最高）
- **命题（可证伪）**：交换机存不下 KV 本体（实测精确匹配表 ~64K×16B），但**存得下"命中指纹 / 线速 INT 遥测"**——把数据面信号当**调度信号源**（KV-aware 路由 / 准入 / 放置），比端站侧估计更优。若**不优**（TTFT/p99 无显著差）→ 止损。
- **最危险邻居（已核实，正面切分）**：**NetKV（KVT-22）**——network cost oracle **明确放在端站、不改数据面/引擎/硬件**（sim 上 TTFT −17.6~21.2%）；llm-d KV-Cache Indexer（主机侧）；ShadowServe（网卡侧取数）；NVIDIA CMX/DOCA Memos（工业界）。
- **最危险近邻**：Foresight Indexing（在网 B+ 树，NCB-6）、CableCache（请求级去重，NPD-1）。
- **最小闭环**：先纯软件仿真（租的 Linux / bmv2 + vLLM 或 trace-driven），量化"在网信号 vs 主机信号"的调度差距；真机 artifact 期再上 SPRINT 环境。
- **成本**：中（仿真低；真机依赖实验室）。
- **⚠️ 生死线：导师**（SPRINT 环境/工具链/共作关系）。

### B 线 · 在网/近线 IDS 的漂移维护（不依赖任何人，立刻能动）
- **命题**：iGuard（CoNEXT'24）/FSNIC 式数据面 IDS **部署即冻结**，在漂移下显著退化且**无人测退化、无人做在线维护**；提出"**数据面可算的漂移检测 + 控制面热替换**"闭环，把漂移后精度恢复到部署初值 Δ 以内。
- **最危险邻居**：iGuard/FSNIC（部署但不测漂移）；*Adapting at Line-Speed: In-Network Concept Drift Detection*（SIGCOMM'25，**仅 demo**，无维护闭环）。
- **最小闭环**：bmv2（租的 Linux / RK3588 自带 Linux）+ 公开 trace（UNSW/CIC）+ 复现 iGuard 的 IF/LogicNets；时间切分制造漂移 → 退化曲线 → 维护闭环。
- **成本**：中。

### C 线 · VU13P 前缀去重索引卡（FPGA 工件）
- 工件 genre（FPGA 会议本身 CCF-B）。**前置核实**：VU13P 是否有板载网口（待办 #2）；Vitis P4 不支持 register（NPD-16）→ 需手写 RTL（Corundum）。
- **风险最高**（工程量），导师点头且网口核实后再动。

### D 线 · GateKeeper M0（RK3588，不变）
- **最快见数字**：G1 门冻结（作废占比 ≥10% → IMC 级测量论文，IMC=B）。不依赖任何人。

### 保底 · β（降级）
- 可租 GPU 后算力问题消失。按 [复审 v2 三改](../子代理评审-两方案CCF-B裁决-v2-2026-10-10.md) 执行，目标 **Computer Networks（B 期刊）/ Q2**；**不再追加冲会议 B 的投入**。
