# 智能网络 / AI for Networking（AI4Net）调研

## 0. 元信息

- **关键词 & 同义词**：AI for networking = ML for networking = learning-based networking；AI4Net；traffic classification = encrypted traffic classification (ETC) = traffic analysis；traffic prediction = traffic forecasting = network telemetry-driven prediction；anomaly detection = network anomaly detection = NIDS = intrusion detection；learning-based congestion control = RL-based CC = learned CC；network LLM = LLM for networking = intent-based networking (IBN) = network agent；AIOps = root cause analysis (RCA)；GNN for networking = graph learning；network digital twin (NDT)。
- **查重基线**：本专题只收**新增**。已录于 [文献索引](../../文献索引.md) 他处的 AI4Net 条目：**NetLLM**（NIAC2026-8，LLM for networking）、**IIsy/Planter**（NIAC2026-6/7，在网分类/ML 映射，属子方向 III）、**Astraea**（CGC-14，学习型 CC）、**Pudica/GCC**（CGA-13/CGC-6，云游戏/WebRTC CC）、**DCQCN**（DRE-14，经典 RDMA CC）、**WiFi 数字孪生线上工作**（WTP-27/107/109/111）与 **Szott WiFi×ML 综述**（WTP-5）。
- **与 WTP 专题的分工**：WTP 是**应用到 WiFi 负载预测/削峰**的具体问题；本专题是**方法层**的 AI4Net 全景，二者在"流量预测/数字孪生"上交叉，本专题**只收通用/蜂窝/骨干侧新条目并显式交叉引用 WTP**，不重录。

## 1. 一句话总览

AI for Networking 在 2024–2026 出现三个明显转向：**① 大模型/Agent 全面渗透网络运维**（NetLLM 开篇，2026 年 NetConfArena / Network Arena / WirelessBench / NetAgentBench 等**评测基准**密集涌现，说明领域正从"能不能做"转向"怎么可信地评测"）；**② 学习型方法与"评测可信度危机"同时爆发**（ETC 的标签来源审计 SoK、PQC 演进下分类器被证伪、图 NIDS 的第一性原理重评、学习型 CC 的公平性/对抗测试——四篇**泼冷水**都落在 2026）；**③ 图学习/数字孪生成为网络建模的统一底座**（RouteNet/NDT 综述），但"保真度/可验证性"仍空缺（NDT Factory 用 LLM 合成**可验证**孪生，正是补这个洞）。

## 2. 背景与问题定义

- **为什么需要它**：网络（配置、协议、流量、故障）的状态空间巨大且语义异构，人工规则（静态阈值、手工调参）在规模、加密、动态性面前失效；ML/DL 能从数据中学"感知—预测—决策"，LLM 进一步带来"自然语言意图—配置/诊断"的接口。
- **核心矛盾**：(a) **数据分布漂移**——加密协议升级（TLS 1.3/PQC）、流量构成变化使训练好的模型快速过期（AIN-6/AIN-10）；(b) **评测不可复现**——标签来源、数据集泄漏让 SOTA 数字失真（AIN-9/AIN-17）；(c) **可部署/可验证**——学习型 CC 与 LLM Agent 的决策缺最坏情况保证与安全护栏（AIN-26/AIN-27）；(d) **在线/线速约束**——推理要放进数据面（子方向 III）或近线（iGuard/FSNIC）。
- **评价指标**：分类（acc/F1/跨域泛化/漂移鲁棒性）、预测（MAPE/RMSE）、检测（TPR/FPR/未知类）、CC（吞吐/时延/公平/收敛）、Agent（任务成功率/可复现性/安全性）、孪生（保真度/同步开销）。

## 3. 技术路线分类

### 路线 A：加密流量分类与理解（ETC / Traffic Analysis）
- **思路**：把原始包字节/包长序列/时序统计喂给 CNN/RNN/Transformer，识别应用/业务/恶意类别，即使载荷加密。
- **奠基与经典**：**Deep Packet**（AIN-1，1D-CNN 直接吃字节）、**DL for ETC: An Overview**（AIN-2，早期综述）、**Deep-Full-Range**（AIN-3，分类+检测一体）、**DISTILLER**（AIN-4，多模态多任务）、**Multimodal DL for ETC**（AIN-5，TNET 系统级）。
- **2023–2025 主线 = 预训练/基础模型**：**DL & pre-training for ETC 综述**（AIN-8，Neurocomputing'25，最新入口）、**ATVITSC**（AIN-7，TIFS'24）、**FlowCLIP**（AIN-11，用域名做对比预训练）。
- **泼冷水（本路线最重要）**：**ETC 数据漂移实证**（AIN-6，模型随协议/流量演进而显著退化）；**SoK: 标签来源审计**（AIN-9，系统质疑 ETC 基准的标签可信度）；**Colossus with Feet of Clay**（AIN-10，**PQC 演进下现有分类器被证伪**）——做 ETC 选题**必须正面切分这三篇**。
- **权衡**：精度↔泛化↔时效；加密越强、协议越新，纯统计特征越脆。

### 路线 B：异常检测与入侵检测（NIDS / Anomaly）
- **思路**：从流/包/日志中检出偏离正常的流量（攻击、故障、异常行为）。
- **奠基（高引）**：**DL-NIDS**（AIN-12，2016；经典）、**DL Approach to NID**（AIN-13，TETCI'18，自编码器无监督）、**NIDS 系统对比研究**（AIN-14，ETT'20）、**网络异常检测×ML 综述**（AIN-15，Access'21）。
- **在网/近线部署（与基座交叉）**：**iGuard**（AIN-16，CoNEXT'24，可编程交换机内跑 Isolation Forest）、**FSNIC**（AIN-19，FPGA SmartNIC 上低延迟流级 IDS）——把"AI4Net"推进到线速。
- **泼冷水**：**First-Principles Evaluation of Graph NIDS**（AIN-17，重评图神经网络 NIDS 的真实增益）、**Three-Axis Stress Test: LLM vs Classical ML for NIDS**（AIN-18，分布漂移+对抗规避下 LLM 未必优于经典 ML）。
- **权衡**：检出率↔误报↔未知攻击泛化；数据集（NSL-KDD/CIC-IDS）老旧与泄漏问题被 AIN-17 点名。

### 路线 C：学习型拥塞控制与传输（Learning-based CC）
- **思路**：用 RL/在线学习替代手工设计的 CC 规则（AIMD/ECN 阈值）。
- **奠基与经典**：**Classic Meets Modern (PCC-Vivace)**（AIN-20，务实化里程碑）、**ACC**（AIN-21，SIGCOMM'21，自动 ECN 调参）、**RL for Datacenter CC**（AIN-22）、**GraphCC**（AIN-23，图学习把拓扑纳入 CC）。
- **2025 新作**：**Jury**（AIN-24，EuroSys'25，公平性**可泛化**）、**EchoCC**（AIN-25，ToN'25，码本精化）。
- **泼冷水**：**Learning-Based vs Human-Derived CC**（AIN-26，实证揭示学习型 CC 根本局限、难上生产）、**CCLab**（AIN-27，对学习/非学习 CC 的统一**对抗测试**）。
- **与本工作区交叉**：Astraea（CGC-14）、Pudica（CGA-13）、WebRTC GCC（CGC-6）、DCQCN（DRE-14）已录，不重复。
- **权衡**：性能↔公平↔可部署（训练成本、硬件卸载如 SmartNIC/NIC in-network）。

### 路线 D：网络大模型 / LLM Agent / AIOps
- **思路**：用 LLM 做意图理解（自然语言→配置/策略）、网络诊断（根因分析）、以及多智能体自动运维。
- **IBN / LLM 配置**：**LLM 意图抽取（5G Core）**（AIN-29，早期代表）、**IBN 配置用 LLM**（AIN-30，IJNM'24）、**LLNet**（AIN-31，TNSM'25，小语言模型指令化设备）、**Agentic IBN for 6G**（AIN-42）。
- **LLM 做预测**：**Spatial-Temporal LLM for Traffic Prediction**（AIN-28，MDM'24，高引）、**CoT 增强 in-context 的移动流量预测**（AIN-38）。
- **AIOps / RCA**：**AIOps 异常检测+RCA 综述**（AIN-32，最新入口）、**LLM 用于 BGP 安全**（AIN-33）。
- **Agent 评测基准（2026 密集涌现，领域新焦点）**：**NetConfArena**（AIN-40）、**Network Arena**（AIN-41）——都在建"可执行/可复现"的 Agent 评测，说明**当前缺 ground-truth 与安全护栏**。
- **最危险邻居**：**NetLLM**（NIAC2026-8，已录，SIGCOMM'24，LLM-for-networking 的开篇）——本路线任何新工作都必须与它切分。
- **权衡**：语义理解/泛化强 ↔ 幻觉/不可验证/时延高/成本高。

### 路线 E：图学习 / 数字孪生 / 流量工程与资源管理
- **思路**：把拓扑/流/业务建成图，用 GNN 做网络建模、预测与优化；或建网络数字孪生做"先仿真后下发"。
- **GNN 网络建模奠基**：**GNN for SDN 建模优化**（AIN-34，SOSR'19）、**GNN×通信网络应用综述**（AIN-35）、**RouteNet-Fermi**（AIN-36，TNET'23，性能建模代表系统）；DRL 与 GNN 结合的 TE（见 §8 附：10.1016/j.comcom.2022.09.029）。
- **数字孪生**：**NDT: Context/Enabling**（AIN-37，IEEE Comm Mag'22，定位性综述）、**NDT Factory**（AIN-43，用多智能体 LLM 合成**可验证**孪生）、RouteNet/NDT for 6G（见 §8）。
- **与 WTP 交叉**：WTP-27/107/109/111 已覆盖"WiFi 数字孪生做预测/配置"，本专题不重录。
- **权衡**：模型保真度↔同步开销↔可验证性。

## 6. 应用 / 已有研究（AI4Net 落在哪些场景）

- **无线/WiFi**：WiFi 负载预测、数字孪生削峰 → 见 [WiFi 负载预测与高峰传输调研](../WiFi负载预测与高峰传输/WiFi负载预测与高峰传输调研.md)（WTP，136 条）。
- **在网/数据面**：把 ML 推理搬进交换机/网卡 → 子方向 III（在网智能）与本专题路线 B/A 交叉（iGuard/FSNIC/Quark）。
- **数据中心/RDMA**：学习型 CC 与 ECN 调参 → 与 [DPDK / RDMA / eBPF 专题](../../文献索引.md)（DRE）交叉。
- **LLM serving**：以 KVCache 为中心的调度本身也是"AI for systems" → 见 [在网计算与LLM serving调研](../在网计算-LLM/在网计算与LLM%20serving调研.md)。
- **工业界**：Cisco（Mist AI）、华为（iMaster NCE-CampusInsight）、NVIDIA 等已把 AIOps 产品化——**本专题最危险的邻居**（见 §7 与 WTP §13 待核实）。

## 7. 研究空白与待解决问题

1. **评测可信度本身成为研究点（2026 最强信号）**：SoK 标签来源（AIN-9）、PQC 证伪（AIN-10）、图 NIDS 第一性原理重评（AIN-17）、学习型 CC 的公平/对抗（AIN-24/26/27）——**"重测/审计已有 SOTA"是被顶会接受的独立贡献**，且门槛（数据+实验）比"再造一个新模型"低，适合硕士周期。
2. **LLM/Agent 网络操作缺"可验证 + 安全"闭环**：NetConfArena / Network Arena / WirelessOpsAgent / NetAgentBench 在 2026 密集出现，**说明当前没有公认的、可复现的 Agent 评测与护栏**；"沙箱内可验证的网络 Agent 决策"是明确空白。
3. **学习型 CC 的公平性与可部署性未解**：Jury 指向公平性泛化，CCLab/Learning-vs-Human 指向对抗与生产化——仍有空间（且 PC 上 Mininet/真实协议栈即可复现，评估成本低，见 NIAC2026 方法学注脚）。
4. **数字孪生的保真度/可验证性**：NDT Factory 用 LLM 合成**可验证**孪生，恰好补"孪生不可信"的洞；与 WTP 数字孪生线交叉。
5. **漂移/在线更新下的在网模型**（与子方向 III 交叉）：数据面内模型（iGuard/FSNIC）一旦部署即冻结，**协议/流量漂移下如何在线维护**缺工作。
6. **最危险的邻居**：① 工业界 AIOps（Cisco Mist AI / 华为 CampusInsight，产品化领先学术评测）；② 已有大型综述（IEEE COMST 系列、ACM CSUR "ML for Computer Systems and Networking"、JISA "comprehensive survey on ML for networking"）——**综述已饱和，不要再写综述型硕士论文**；③ 本工作区 WTP 已占"WiFi 预测/数字孪生削峰"。
7. **泼冷水证据（必须在动机章节正面处理）**：AIN-6（漂移退化）、AIN-9（标签不可信）、AIN-10（PQC 证伪 ETC）、AIN-17（图 NIDS 增益存疑）、AIN-18（LLM 未必优于经典 ML）、AIN-26（学习型 CC 难上生产）。
