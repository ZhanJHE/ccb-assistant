## 0. 元信息

- **关键词 & 同义词**：in-network computing = in-network computation/processing；programmable switch = P4 switch = Tofino = programmable data plane (PDP)；in-network aggregation (INA) = in-network reduction；in-network caching = in-network key-value；SmartNIC = DPU = IPU = BlueField = Pensando；RMT = match-action pipeline；INT = in-band network telemetry。
- **查重基线**：本专题只收**新增**。已录于 [文献索引](../../文献索引.md) 他处的基座条目：SwitchML/ATP/OmniReduce/NetCache/NetChain/IIsy/Planter/OmNiCCL（NIAC2026-1~12）、OrbitCache/CableCache/Pegasus/FENIX/NetCache 数字（NPD-1~7）、DPA-Store（NIAC2026-20）、BEACON/COER/DFlush（DRE-23~25）、RDMA/拥塞控制奠基（DRE-9~20）。

## 1. 一句话总览

2024–2026 在网计算基座出现三个明显转向：**① Tofino 停产倒逼"平台多元化与可移植性"**（OptimusPrime 可变形架构、MatchBox 可移植语义、Rearchitecting 全栈反思）；**② SmartNIC/DPU 从"固定功能卸载"升级为"通用数据面系统"**（Presto 把完整 TCP 塞进 RMT、SCENIC/BALBOA 重构网卡计算、Gryphon 生产级 DPU 网关、SmartNIC 首份性能模型）；**③ 在网聚合进入"语义扩展 + 收益重估"阶段**（Shesha 异步 DRL、DSA 内存调度、ToN'25《Revisiting INA》泼冷水）。

## 2. 背景与问题定义

- **为什么需要它**：AI 集群通信占比持续上升，端站 CPU 成为数据搬运瓶颈；交换机/网卡在流量必经之路上，"路过即计算"可同时省 CPU、省 RTT、省能耗。
- **核心矛盾**：(a) 片上 SRAM/TCAM 量级（NetCache 实测 64K×16B 精确表）vs 应用状态规模；(b) RMT 流水线**单向 lock-step** vs 协议的依赖状态更新（Presto 的核心痛点）；(c) 无浮点/算子受限 vs 计算语义；(d) 多租户隔离与确定性；(e) **平台锁定**——Tofino 停产（PCN 827577-00）后，代码/环境/采购全面受限（详见 NPD-17）。
- **评价指标**：线速/吞吐（Tbps、Bpps）、资源占用（SRAM/TCAM/stage/管线通过率）、延迟（µs 级）、能效（throughput-per-watt）、表项规模、控制面同步开销。

## 3. 技术路线分类

### 路线 A：在网聚合与训练通信原语（INA 线增量）
- **思路**：多对一归约放进交换机寄存器。经典 SwitchML/ATP/OmniReduce（NIAC 已录）解决"梯度求和"；近两年扩展到**新同步模式、新互连、内存调度、收益重估**。
- **新增**：
  - **Rina**（NCB-1，**ICNP'24**——文内 Thanks 注明 "To appear in ICNP 2024"，arXiv 为预览版）：PS incast 与 Ring-AllReduce 长尾之间取中，INA 增强 RAR；自称同硬件成本下吞吐超 ATP 50%。
  - **Shesha**（NCB-4，CoNEXT/PACMNET'25）：**异步 DRL** 的机会式在网加速——聚合语义从"同步梯度"扩展到"非同步更新"。
  - **DSA**（NCB-34，题录级）：INA 的**数据面内存调度器**——"槽位/内存"成为一等资源。
  - **P4INC-AOI**（NCB-3，ToN'25）：全光互连 + 在网聚合，INA 叙事延伸到光交换。
  - **⭐ Revisiting INA**（NCB-2，ToN'25）：**对在网聚合的系统性重估——本路线最重要的"泼冷水"候选，动机章节必读**（无 OA，待获取）。
- **权衡**：寄存器容量/分片轮询/算子受限的老约束未变；新问题是"哪些新 workload（MoE、异步 RL、推理 KV）值得聚合"。

### 路线 B：在网查找 / 缓存 / 重排原语
- **思路**：交换机做"索引与顺序"而非"值"。NetCache/NetChain/Pegasus（已录）证明目录可行；OrbitCache/CableCache（NPD 已录）推缓存/去重边界。
- **新增**：
  - **CRAM**（NCB-5，NSDI'25，Varghese 组）：CAM+RAM 统一评估框架 + 三个新 IP 查找；RESAIL 在 Tofino-2 上撑 **225 万 IPv4 前缀**（纯 TCAM 仅 25 万）——"TCAM+SRAM 混合算法"方法论。
  - **Foresight Indexing**（NCB-6，INFOCOM'26，Tong Yang 组）：**B+ 树索引加速放进路径上的交换机**——"在网索引"又一占位者，KV 前缀目录路线（见在网KV前缀去重调研）必须正面切分。
  - **ConWeave**（NCB-7，SIGCOMM'23[经典补录]）：交换机内**重排**屏蔽乱序 → RDMA 逐包级负载均衡；后续 DCP（SIGCOMM'25）/CAVER（SIGCOMM'24 poster）/LEFT（APNet'24）构成"网内重排"小谱系（传输侧归 KVT/DRE）。
- **权衡**：查找类工作的天花板是表项与 stage；重排类工作的天花板是片上队列与尾延迟。

### 路线 C：新架构与表达能力边界（Tofino 之后的"基座之问"）
- **OptimusPrime**（NCB-8，SIGCOMM'24）：同构硬件块**可变形**架构，打破 pipeline vs run-to-completion 二分；FPGA 原型 + 软件 ASIC 模拟器验证。
- **Rearchitecting Programmable Networks for INC**（NCB-9，EuroSys'26）：从硬件到语言的全栈反思（引用 OptimusPrime）。
- **How to Execute Any Computable Function on PDP**（NCB-10，INFOCOM'26）：数据面**表达力边界**的形式化追问。
- **ARDAPL**（NCB-33，题录级）：有状态包处理的自适应韧性数据面。
- **判断**：这条路线回答"Tofino 死了之后基座长什么样"，是选题期必须跟住的范式层讨论。

### 路线 D：SmartNIC/DPU 通用数据面系统（本轮最大增量）
- **Presto**（NCB-11，SIGCOMM'26）：**首个 RMT 流水线上的完整 TCP**——乐观并发 + 伪段注入 + bump-in-the-wire，把依赖状态更新折进单向流水线；省 16 个 host CPU 核、99.99p 尾延迟 5×↓、能效 2×；Tofino2 原型近 1 Bpps。**方法论意义大于 TCP 本身**：任何"有状态协议上 RMT"都可套这三招。
- **SCENIC**（NCB-13，arXiv'26，Alonso 组）：流计算增强 SmartNIC，调和"商用卡高带宽易集成 vs 研究卡可定制"的矛盾。
- **RoCE BALBOA**（NCB-14，arXiv'25，Alonso 组）：SmartNIC 上的服务增强 RoCE。
- **Network-accelerated Active Messages**（NCB-15，arXiv'25，Stephens/Stutsman/Antichi）：网内 Active Messages，补 RDMA"语义贫乏、多 RTT"的短板。
- **Gryphon**（NCB-16，arXiv'25，ByteDance 生产）：Pbps 级多租户网关，**ASIC+DPU 分级协同卸载**——工业界对"基座该放哪"的最新回答。
- **Palladium**（NCB-17，arXiv'25）：DPU 多租户 serverless 数据面 + 零拷贝跨节点 RDMA。
- **Towards Simple Models of Complex SmartNICs**（NCB-12，arXiv'26-09，Varghese/D.Kim）：**BF-3 等异构网卡的第一份"简单性能模型"**——性能预测/调度/仿真的地基，空白的首个占位。
- **权衡**：DPU 算力弱（BF-2 8×A72）、内存带宽窄（ShadowServe 自认瓶颈）；但"路径上 + 有 CPU + 有内存"使其成为基座最活跃载体。

### 路线 E：P4 语言 / 编译 / 可移植性
- **Parasol**（NCB-18，ToN'24，Rexford/Walker）：参数化数据面程序自动调优，2 小时内比肩手工优化 P4。
- **Prose-to-P4**（NCB-19，arXiv'24，Raiciu 组）：高级语言→P4/NPL，降开发门槛。
- **MatchBox**（NCB-20，PACMPL'26，Akella/Dillig）：**数据面可移植性的语义学基础**——Tofino 停产后"一次编写、多 target"的理论支点。
- **P4XC / T4G**（NCB-32/35，题录级）：异构处理器统一编译框架；trace 驱动 P4 程序生成。
- **关联**：Kugelblitz（2023，可执行的成本感知流水线 DSE，引自 OptimusPrime 引用列表）——设计空间探索先驱，未编号。

### 路线 F：遥测 / 测量基座
- **Söze**（NCB-21，OSDI'25）：**商用交换机的简单遥测就足够**驱动大规模逐流加权带宽分配（去中心化）——"遥测→控制"闭环最小依赖的证明。
- **OmniPath Ping（OPP）**（NCB-22，SIGCOMM'26）：逐包喷洒时代的主动测量原语。**更正：NPD 旧待办"OPP=在网去重"证伪，实为测量工作。**
- **MPINT**（NCB-23，CoNEXT'25 WS）：在网去重实现轻量多路径 INT（NPD 旧待办核实通过）。
- **Confluence**（NCB-36，题录级）：多流水线数据面的监控精度。
- **本组 SPRINT**（NCB-26，INFOCOM'26）：线速 INT 恢复——实验室在遥测基座上的自有资产。

### 路线 G：本组（Cui Lin/AntLab）基座工作
- **Carlo**（NCB-24，INFOCOM'24）+ 期刊扩展（NCB-25，IEEE TC'25）：跨平面协同部署多个在网计算应用——解决"一块交换机跑多个 INC 应用"的资源编排。
- **SPRINT**（NCB-26，INFOCOM'26）：见路线 F。
- 交叉：Quark（INFOCOM'25）/Monic（INFOCOM'26）属子方向 III（在网推理），平台能力证明见 [在网KV前缀去重调研](../在网计算-LLM/在网KV前缀去重调研.md) §3 路线 E。

## 7. 研究空白与待解决问题

1. **SmartNIC 可理解模型刚起步**（NCB-12 是 2026-09 才出现的首个建模尝试）：性能预测、放置调度、高保真仿真全建立在地基缺失上 → **做"模型/仿真"类论文窗口期**。
2. **可移植性工程系统缺位**：MatchBox 给了语义基础但无工具链；Parasol 调优不跨 target。"一次编写、Tofino/Pensando/BF/FPGA 多端运行"在 Tofino 停产后是真痛点。
3. **聚合语义未系统化**：梯度（SwitchML）→ 异步（Shesha）→ 内存调度（DSA）逐点出现，但"什么语义适合在网聚合"缺分类学；KV 控制面聚合（ACK/元数据）仍空白（承 [在网计算与LLM serving调研](../在网计算-LLM/在网计算与LLM%20serving调研.md) 空白 6）。
4. **有状态协议上 RMT 的通用框架**：Presto 解决了 TCP，但 QUIC/自定义 RPC/KV 传输协议各要重写一遍三招——"协议→RMT 编译器"没人做（与 HTO 专题交叉）。
5. **遥测→控制闭环的基座化**：Söze 证明最小依赖可行，但"遥测原语→在线控制"缺可复用组件（本组 SPRINT+Carlo 恰在两侧各有一块）。
6. **最危险的邻居**：工业界——NVIDIA SHARP/Spectrum-X（在网聚合工业实现）、DOCA DPL（P4 变体锁定）、AMD Pensando（P4 原生 DPU）；学术——Foresight Indexing（在网 B+ 树）与 KV 前缀目录选题正面相邻。
7. **泼冷水证据**：NCB-2《Revisiting INA》（ToN'25，待获取全文）；OrbitCache 对 NetCache 容量叙事的证伪（NPD-2）；NCB-12 对"SmartNIC 性能直觉"的纠偏潜力。
