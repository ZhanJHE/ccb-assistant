# M0 实验计划：作废字节测量（4–6 周）

> 目标：造出全文地基的两个数字——**作废字节占总流量比例**、**作废对高峰 95 分位负载的抬升量**。
> 裁决门 G1 的判据见 `../AGENTS.md`。本计划的口径对齐调研 §12：测的是"已传字节的作废率"，不是"续传能力有无"。

## 1. 测试床（第 1–2 周）

```
[民用 PC]──┐                    ┌── 家用 WiFi AP ── 公网（真实大文件/视频）
[手机  ×2]─┼─ WiFi ──[RK3588 网关: OpenWrt]──┤
[PC 有线]──┘                    └── 有线直连 ── 自建服务器（无 Range HTTP / 对象存储）
```

- **网关**：RK3588 刷 OpenWrt；nftables/tc 做整形；netem 注入剖面。
- **采集**（三件套，全部带 monotonic 时钟时间戳）：
  1. per-flow 字节记账（conntrack + 定时快照，或 nfdump/softflowd）；
  2. 应用层日志：客户端下载器记录每次请求的字节范围、响应码（200/206）、ETag、完成/中断状态；
  3. 链路负载时间序列（网关接口计数器，1s 粒度）。
- **作废字节的判定口径**（写死在分析脚本里）：
  - 对象级：同一对象被重复传输的字节数 = Σ（后续尝试已传字节 ∩ 前次已传字节）；
  - 块级：部分下载块被丢弃的字节（块校验系统）；
  - 预取/切换级：已下载但未消费的字节（对照播放/使用日志）。
- **验收**：空跑 1 天，三件日志能对齐到同一会话，字节数误差 <1%。

## 2. 三类作废场景（第 3–5 周）

### 场景① 对象级重启（机制 A/B）
- 自建无 Range HTTP 服务（禁 `Accept-Ranges`）+ 公网真实大文件下载对照组；
- 用 netem 在传输中途注入中断（断链 5s/30s/换 IP 模拟 WiFi↔蜂窝切换）；
- 变量：对象大小（10MB/100MB/1GB）× 中断点（25%/50%/75%）× 客户端类型（支持续传 vs 不支持）；
- 测：重下产生的额外字节、重复传输系数（总传字节/对象大小）。

### 场景② 预取/切换作废（机制 C/D）
- 家用 WiFi 下刷短视频（固定脚本滑动节奏）与 ABR 长视频，复现 WTP-37/39 口径；
- 用播放日志对齐下载日志，判定"已下载未消费"字节；
- 测：作废率，并与 33%/45.2% 文献数字对照（我们测的是家用 WiFi + 当前 App 版本）。

### 场景③ 高峰放弃-重试（因果链核心）
- 多流并发注入高峰剖面（按自采家庭负载 trace 的晚高峰形状整形）；
- 模拟用户耐心：传输速率 < 阈值持续 7–10s（WTP-73 口径）即放弃，延迟 t 后重试（t ∈ {立即, 5min, 30min}）；
- 测：作废字节随负载水平的函数、重试字节对高峰 95 分位利用率的抬升（有/无作废两种注入模式做 A/B）。

## 3. 产出物（第 6 周）

1. 两个核心数字 + 置信区间：作废占比、高峰 95 分位抬升量；
2. 分类学占比：A/B/C/D 四类机制各占多少；
3. 可公开 trace 数据集（脱敏）；
4. 一份负载预测训练集（网关负载时间序列，Phase 2 预测器用）。

## 4. 统计与方法学纪律

- 每场景 ≥ 5 个独立时段重复，报中位数 + 95% CI；
- 工作日/周末分开报告；高峰/非高峰分开报告；
- 与文献数字对照时注明口径差异（平台、年份、加密比例）；
- 必须正面引用反方 WTP-122：若我们的作废占比小，明确讨论"与 Hu & Seetharam 一致的解释"。

## 6. 数据来源（2026-10-02 修订：放弃一切"长期挂机真实采集"）

**约束确认**：RK3588 不可带回家 7×24；实验室人少无真实高峰，被动采集亦不可行。
→ 数据策略定为 **公开 trace（负载背景）+ 剧本化合成家庭（高峰制造）+ 受控实验自产（作废场景）** 三件套。

### 6.1 负载背景与高峰形状：公开 trace
- 候选源（**用前逐站核实可用性，读 WTP-1/2/4/26/27 时顺手查它们的数据集是否开源**）：
  - CRAWDAD（Dartmouth 校园 WiFi，多年期 SNMP 负载序列）——WLAN 负载预测标配；
  - MAWI/WIDE（骨干链路段，包级）；
  - FCC MBA（真实家庭宽带测量，补"家庭"色彩）；
  - 家庭级包级公开 trace 极稀缺，如有发现立即登记 `文献索引.md`。
- **高峰不需要单独"搞"**：任何连续数周 trace 天然含每日高峰窗口，切峰段即可；一月 ≈ 20–30 个高峰样本。

### 6.2 高峰的制造：trace 重放 + 剧本化合成家庭
- **场景③本质就是"造高峰"**：按公开 trace 的峰谷形状用 tc/netem 在实验室链路上整形重放，高峰强度/时长/到达过程全部可控、可重复——受控变量是论文优点而非缺陷。
- **剧本化合成家庭**：几台设备 + UI 自动化脚本按家庭作息驱动（白天心跳、晚间集中刷视频/下载/云同步），制造"合成家庭"流量成分。
- **合成扩展**：以公开 trace 拟合参数（峰谷比、高峰持续、流大小重尾分布、ON/OFF 到达），生成任意长、任意峰强序列做压力扫描。
- 先例支撑：TCC/COMNET 接受仿真为主的评估（KVT-36/37/38/39 门槛证据）；预测器在真实公开 trace 上验证 + 系统层在合成高峰上压测是标准组合。

### 6.3 作废场景数据：自产不变
三个场景均为主动受控实验（单场景数小时可完成），数据全部自产，不依赖任何挂机采集。

### 6.4 论文叙事调整（诚实写法）
> 系统载体：家庭网关级硬件 RK3588（调度器真实运行、真实能耗测量）；
> 负载背景：公开 WLAN/家庭宽带 trace 驱动重放；
> 作废测量：受控实验自产 + 行为参数取自文献（WTP-44/45/73）。
> 局限节写明：无长期野生家庭采集，外部效度由多 trace 源 + 参数扫描补偿。
